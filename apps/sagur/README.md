# סָגוּר — הצעות מחיר שנסגרות

אפליקציית SaaS לבעלי מקצוע עצמאיים: הצעת מחיר מקצועית מהנייד בדקה, הלקוח פותח
קישור, **חותם דיגיטלית** — והמערכת עוקבת אחרי מה נצפה, מה נסגר ומה דורש מעקב.

רץ כ-Cloudflare Worker (Hono + D1) עם פרונט־אנד סטטי שנשמר בטלפון כ-PWA.
בלי בילד סטפ, בלי שרת לתחזק.

## למה דווקא זה

- **קהל שמשלם.** ~400 אלף עוסקים בישראל. שיפוצניקים, מתקיני מיזוג, חשמלאים,
  מעצבים וצלמים שולחים היום הצעות כטקסט בוואטסאפ או כקובץ Word.
- **קשור ישירות להכנסה.** כלי שעוזר *לסגור עסקאות* נמדד מול העמלה על עבודה אחת,
  לא מול מחיר של עוד אפליקציה. ‎₪49 לחודש מוחזרים בעסקה אחת בשנה.
- **דביק.** המחירון, היסטוריית הלקוחות והארכיון של ההצעות חיים במערכת. מי
  שהעביר לשם את המחירון שלו לא עובר למתחרה.
- **לולאת הפצה מובנית.** כל הצעה במסלול החינמי נושאת "נוצר עם סָגוּר" — והקורא
  הוא לרוב בעל עסק בעצמו.
- **עלות תפעול אפסית.** Workers + D1: אלפי משתמשים נכנסים לשכבה החינמית/זולה.

## הרצה מקומית

```bash
npm install
npx wrangler d1 create sagur-db     # פעם ראשונה — הדביקו את ה-database_id ל-wrangler.toml
npm run db:migrate:local
npm run dev                          # http://localhost:8787
```

בדיקות וטיפוסים:

```bash
npm run check      # tsc --noEmit + unit tests
```

## פריסה

```bash
npx wrangler login
npm run db:migrate:remote
npm run deploy
```

אחרי הפריסה כדאי להגדיר ב-`wrangler.toml` את `APP_ORIGIN` לדומיין הקבוע, כדי
שהקישורים שנשלחים ללקוחות יישארו יציבים גם אם ה-Worker נגיש גם דרך
‎`*.workers.dev`.

### תשלומים (אופציונלי)

התשלום בנוי מול Stripe Checkout ומופעל ברגע שמוגדרים הסודות:

```bash
npx wrangler secret put STRIPE_SECRET_KEY
npx wrangler secret put STRIPE_PRICE_ID        # price_... של מנוי חודשי
npx wrangler secret put STRIPE_WEBHOOK_SECRET  # whsec_... מ-Stripe Dashboard
```

ה-webhook מצפה ל-`POST /api/billing/webhook` ומאמת חתימת HMAC לפני שהוא נוגע
בבסיס הנתונים. בלי הסודות האלה מסך השדרוג פשוט אומר שהתשלום המקוון עוד לא פעיל.

**קודי שדרוג ידניים** (ללקוחות ראשונים, החזרים, שותפים):

```bash
npx wrangler secret put LICENSE_CODES   # למשל: SAGUR-EARLY1:365,SAGUR-EARLY2
```

כל קוד הוא חד־פעמי (נשמר ב-`license_redemptions`); הסיומת `:365` מגבילה לימים,
בלעדיה השדרוג פתוח.

## מבנה

```
src/
  index.ts          חיווט ה-Worker: API + עמוד הלקוח + נכסים סטטיים
  auth.ts           PBKDF2 דרך Web Crypto, סשנים בעוגייה
  money.ts          חשבון כספי — הכול באגורות שלמות
  domain.ts         מחזור החיים של הצעה: סטטוסים, תפוגה, מעקב
  plan.ts           הרשאות מסלול ומכסות
  store.ts          גישה ל-D1: מספור, פריטים, חישוב מחדש, לוג אירועים
  public-page.ts    עמוד ההצעה שהלקוח רואה (server-rendered)
  routes/           auth, business, customers, catalog, quotes, public, stats, billing
public/             ה-PWA: index.html, app.js, style.css, sw.js, icons
test/               בדיקות יחידה ללוגיקה הטהורה
schema.sql          סכימת D1
```

### החלטות תכנון

- **כסף באגורות שלמות (INTEGER).** עיגול קורה רק בשורת פריט אחת; משם והלאה הכול
  חשבון שלמים, כך שהסכומים המודפסים תמיד מסתדרים.
- **`expired` נגזר ולא נשמר.** תוקף נבדק מול `valid_until` בזמן קריאה, כך שאין
  צורך במשימה מתוזמנת ואין מצב שהסטטוס במסד "נתקע".
- **הצעה ננעלת ברגע ששולחה.** עריכה דורשת פתיחה מחדש כטיוטה, ואז החתימה נמחקת —
  מסמך חתום חייב להתאים למה שנחתם.
- **עמוד הלקוח מרונדר בשרת.** נפתח מיידית בטלפון, בלי אפליקציה ובלי התחברות.
- **טבלת `quote_events`.** תיעוד מלא של מי פתח, מתי, מאיזה IP — זה מה שנותן
  לחתימה הדיגיטלית משקל.
- **בעל העסק שפותח את הקישור שלו לא נספר כצפייה של הלקוח.**

## API

| נתיב | תיאור |
|---|---|
| `POST /api/auth/register\|login\|logout\|password` | חשבון וסשן |
| `GET /api/auth/me` | מצב הסשן: משתמש, הרשאות, ניצול מכסה |
| `GET/PUT /api/business` | פרטי העסק שמופיעים בראש ההצעה |
| `GET/POST/PUT/DELETE /api/customers` | לקוחות (מחיקה של לקוח עם היסטוריה = ארכוב) |
| `GET/POST/PUT/DELETE /api/catalog` | מחירון |
| `GET/POST/PUT/DELETE /api/quotes` | הצעות |
| `POST /api/quotes/:id/send\|status\|duplicate` | מחזור החיים |
| `GET /api/stats` | לוח הבקרה |
| `GET /q/:token` | עמוד ההצעה של הלקוח |
| `POST /api/public/q/:token/approve\|decline` | תשובת הלקוח |
| `GET /api/billing`, `POST /api/billing/checkout\|redeem\|webhook` | מסלול ותשלום |

## מה הלאה

- תזכורת מעקב אוטומטית ללקוח שלא ענה (מייל/וואטסאפ).
- הפיכת הצעה שאושרה לחשבונית — או ייצוא למערכת חשבוניות קיימת.
- תמונות בשורת פריט (לפני/אחרי, דגם מוצר).
- מספר משתמשים לאותו עסק.
